### Top 5 New Metrics to Implement

#### 1. Expected Booking (xB) + fouls-won dead-ball value — two-sided discipline model · **Priority: HIGH** (NEW)
**What:** A two-sided model of fouling. (a) **xB** = P(a foul → yellow card), per the 2024 Expected Booking model — fit on foul events with features: pitch location (x/y), foul type, whether it stopped a promising attack, game minute, score-state. Aggregate to **fouling efficiency** = fouls committed per booking (high = "smart fouls"; the tactical-foul signal) and **cards over/under expected**. (b) The offensive mirror — **fouls-won dead-ball value** = expected free-kick/penalty xG generated by fouls a player/team *draws*, by zone, reusing the FK-zone danger already in `set_pieces.py:compute_dangerous_fk_zones`.
**Why:** The app models almost everything offensive but has **no discipline analytics at all** despite the constants being in place (`config.py:42` `EVENT_FOUL=4`, `:55` `EVENT_CARD=17`, `:147` `CARD_TYPE_MAP`). Discipline is decisive in Liga MX/CONCACAF knockouts (suspensions, 10-man games), and "tactical foul efficiency" is a real coaching KPI. Highest payoff because it opens a whole untouched analytical surface with data already extracted.
**Compute (`processing/discipline.py`):**
```python
fouls = events[events.typeId == 4]                    # EVENT_FOUL
cards = events[events.typeId == 17]                   # EVENT_CARD; CARD_TYPE_MAP for YC/RC
# label a foul as 'booked' if a card by same player within ~same dead-ball window
fouls["booked"] = link_card_to_foul(fouls, cards, window_s=10)
# xB: gradient-boosted P(booked) on [x, y, foul_type, stops_attack, minute, score_state]
xb = GradientBoostingClassifier().fit(X, fouls.booked).predict_proba(X)[:,1]
fouls_per_booking = len(fouls) / max(cards_yellow, 1)  # fouling efficiency
# offensive mirror: fouls WON in FK-danger zones -> expected dead-ball xG
drawn_value = dangerous_fk_zones(team_id)             # reuse set_pieces.py
```
Start with a logistic/GBM xB on the local Opta corpus (77 comps gives ample fouls); guard player splits with `MIN_APPEARANCES_FOR_RATING`. Surfaces on **Tactics** (team fouling profile) and **Player Intelligence** (an "enforcer" / "foul-magnet" badge).

#### 2. Set-piece second-phase xG + per-routine Shot Ratio / Goal Ratio · **Priority: MEDIUM** (NEW — second-phase layer)
**What:** Extend the set-piece engine from *first-shot attribution* to the **StatsBomb HOPS-style** output: per routine type (corner / inswinger-outswinger / short / indirect FK / direct FK), report **xG per set piece**, **Shot Ratio** (% of set pieces producing a shot), **Goal Ratio**, and crucially **first-phase vs second-phase xG** (initial delivery vs the recycled/second-ball attack). `set_pieces.py` already links shots in a 45-s window (`SET_PIECE_WINDOW_SECS`) — split that window into the initial-contact shot (≤~6 s) vs second-phase shots (6–45 s, after a clearance/recycle).
**Why:** Set pieces are the live tactical story of 2025–26 — ~28% of Premier League goals now come from dead balls, and the elite edge is the **second phase** (Newcastle's model). The app captures first-shot xG but throws away the second-phase signal, which is exactly where the modern coaching value sits. Pure extension of a shipped module — low risk, high topicality.
**Compute (`processing/set_pieces.py`):** in `_attribute_shots_to_set_pieces`, tag each linked shot `phase = "first" if dt <= FIRST_CONTACT_S else "second"` (reuse the clearance detection already in `corner_defense.py:compute_second_ball_control`); then `groupby([routine_type, phase]).agg(xg=sum, shots=count) ; shot_ratio = n_with_shot / n_routines`.

#### 3. Throw-in / long-throw threat model · **Priority: MEDIUM** (NEW)
**What:** Treat throw-ins — especially **long throws into the box** — as a valued set-piece. Per throw: **xG generated** within ~6 s, a **long-throw flag** (delivery into the penalty area from a throw origin near the byline), and team-level **throw-in xG/100 throws** split attacking-third vs defensive-third.
**Why:** Long throws are the breakout 2025–26 trend (PL throw-in goals **more than doubled** YoY to ~0.12/match; Opta's own "is the league more direct?" pieces lead on it). The app has **no throw-in handling whatsoever** — and long throws are precisely the kind of low-cost, high-leverage tactic a club like América can adopt. Genuinely net-new and directly actionable.
**Compute (`processing/wide_play.py` or `set_pieces.py`):** throw-ins are passes (`typeId == 1`) carrying **qualifier 107 ("Throw-in")** — add `extract_throwins()` mirroring `extract_crosses`; long-throw = throw whose end coords land in the box (`x>83 & 21<y<79`); link to next shot by per-match time window (⚠️ **link per match, never on merged season events** — same minute-reset cross-leak gotcha that bit `wide_play.link_cross_xg`). `xg_per_long_throw = linked_shot_xg.sum()/n_long_throws`.

#### 4. Stretch Index / last-line defensive compactness · **Priority: MEDIUM** (NEW)
**What:** Two team-shape numbers the app doesn't have, both event-tractable from average positions: (a) **Stretch Index** = area of the convex hull of the four deepest outfielders (the back line) — small = compact last line, large = stretched/exposed; (b) **last-line exposure** = mean distance from the three most advanced attackers to their nearest defender. Report in- vs out-of-possession and by game phase.
**Why:** `formations.py` already gives a defensive **line height** (a single y-value) but nothing about the **shape/area** of the block — and shape is what determines whether a line is genuinely compact or merely deep. The Stretch Index is the named, literature-backed metric for exactly this. It also finally justifies the long-queued **convex-hull visualization** (Viz #1) with a concrete metric behind it.
**Compute (`processing/team_shape.py`):**
```python
from scipy.spatial import ConvexHull
avg_pos = mean_positions(events, team_id, in_possession=False)   # reuse tactical_positions.py
back4 = avg_pos.nsmallest(4, "x")                                # deepest outfielders (own goal = low x)
stretch = ConvexHull(back4[["x","y"]].values).volume            # 2D area
exposure = mean(nearest_def_dist(top3_attackers, defenders))
```
Coordinates are normalised 0–100 (per `viz/pitch.py`), so the area is directly comparable across matches. **Honesty note:** average-position hulls are an event-data approximation of the true (tracking) compactness — flag it as such; it captures structural tendency, not instantaneous shape.

#### 5. Player-level Defensive Action Value (xT-prevented) · **Priority: MEDIUM-HIGH** (NEW — player slice)
**What:** Credit each *defensive* action (tackle `typeId 7`, interception, clearance, block, recovery) with the **threat it prevented** — the xT of the opponent's possession state that the action terminated, à la the 2025 ML defensive-valuation work and the defensive slice of VAEP/OBV. Output a per-player **xT-prevented per 90** and a team **threat-suppression** total.
**Why:** This is the single biggest *quality* gap in player evaluation. Per memory ([[def-rating-is-league-percentile]]), the Scouting **DEF rating is currently just a league percentile of raw counts**, and `xdef.py` is **team-only** — so a defender who makes high-value interceptions in dangerous zones scores the same as one racking up cheap clearances. Valuing the action by xT-prevented fixes that and feeds a real DEF rating.
**Compute (`processing/action_value.py`, defensive slice):** for each defensive action, `prevented = xt(opponent_state_before_action)` using the existing `xt.py` grid evaluated at the location/possession the action ended; `groupby(player).sum()/per90`. ⚠️ Per [[def-rating-is-league-percentile]]: to fold this into FC ratings it must be **percentiled across a league-wide scan**, not normalised within one team — budget a cached `compute_league_defensive_value` (single partidos pass, like `compute_league_gk_value`). Respect `MIN_APPEARANCES_FOR_RATING`.

### Emerging techniques (where the industry is moving)

- **EPV reborn as reward/risk dual pass models.** The 2025 "Revisiting Expected Possession Value" work (U-Net CNN over the pitch, ball-height-aware passes, **separate reward and risk** components) is the new state of the art for possession value — the principled version of our queued pass risk/reward and VAEP/OBV carry-overs. Direction for `action_value.py`, not a near-term build (needs a trained CNN).
- **"Matches as language" keeps accelerating.** EventGPT (arXiv 2512.17266) and probabilistic shot-occurrence frameworks (arXiv 2512.00203) model event sequences as tokens to value player impact — conceptually adjacent to OBV/VAEP and our `sequences.py`. Note as frontier.
- **Discipline/causal modeling is going mainstream.** Expected Booking (xB) brings the "expected" residual treatment to fouls — our #1 is the event-data-tractable version, and it's a clean fit because the foul/card constants already exist.
- **The set-piece & long-throw revolution is the tactical headline of 2025–26.** Dead balls now ~28% of PL goals, throw-in goals doubled YoY, and the elite edge is the **second phase** — our #2/#3 chase exactly this with shipped extractors.
- **Spatial-control defense.** Prediction-based back-four evaluation with pitch control (arXiv 2511.06191) and HOPS aerial metrics (Hudl StatsBomb) are the defensive frontier — but full pitch control / spatial control is **tracking-bound**; our Stretch Index (#4) is the honest event-data approximation. Do not fake pitch control from events.
- **Tracking-only frontier (flag, don't chase):** true pitch control/Voronoi, Dynamic xT off-ball weighting, TacticAI-style GNN set-piece setups, pressing intensity via velocities, receipts-in-space. One honest "future work with tracking data" note beats a fake event-data version.
- **Data-access watch (operational, carry-over):** FBref lost its Opta licence Jan 2026; the app reads a *local* Opta corpus so it's insulated, but the pan-European similarity loader (`player_profile.py`) cannot assume it can refresh from FBref. Keep the note in `11_Data_Sources`.
